# The systems this abstract agent needs

Nine systems, named by role rather than by product. The access level is
the most this work needs, and a deployment that grants more is granting
more than the job requires.

| Role | Access | What the access is for |
|---|---|---|
| the value creation plan | write | The plan at every version, with what changed and why, and this agent issues it. |
| the commitment tracker | read | Each change's owner, date and state, which progress is read from. |
| the watch list | write | A board decision that moves the company's standing is entered at a new version, beside the portfolio-monitor agent, which keeps the list. |
| the portfolio reporting system | read | The company's reports, which each measure is read from. |
| the company's financial records | read | The people, cash and costs that decide what the company can carry. |
| the data room | read | The diligence findings under each starting point. |
| the decision record | read | The committee's conditions the plan has to carry. |
| the board portal | read | The board pack and the papers the director's brief is written from. |
| the calendar | write | The sessions where management's view is heard and the plan is shaped. |

Whoever builds an agent from this plugin writes the `mcp.json` that
points these roles at their own systems. Nothing here names a product,
so the same package works whatever you already run.
