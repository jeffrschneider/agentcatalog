# The systems this abstract agent needs

Nine systems, named by role rather than by product. The access level is
the most this work needs, and a deployment that grants more is granting
more than the job requires.

| Role | Access | What the access is for |
|---|---|---|
| the cap table record | write | The rebuilt capitalization, the fund's position from the closing date, every change through the hold and the close at zero live here, and this agent keeps them. |
| the data room | read | The charter, the share register, every issue and transfer, the option plan and the executed agreements. |
| the request log | write | Each gap between the company's records and its own table is logged against the record that would close it. |
| the financial model | write | The ownership and preference schedules the returns are computed from. |
| the deal pipeline | read | The structure proposed and the agreed text the closing capitalization is read against. |
| the close plan record | write | The funds flow lines the cap table sets, and a capitalization difference entered as a condition to closing. |
| the fund accounting system | read | The cost booked against each holding, which the recorded position must match. |
| the brokerage account | read | The trades, confirmations and settlements each sale of listed shares is reconciled to. |
| the notification channel | write | A difference that holds a closing or a payout reaches the deal lead the same day. |

Whoever builds an agent from this plugin writes the `mcp.json` that
points these roles at their own systems. Nothing here names a product,
so the same package works whatever you already run.
