# The systems this abstract agent needs

Eight systems, named by role rather than by product. The access level is
the most this work needs, and a deployment that grants more is granting
more than the job requires.

| Role | Access | What the access is for |
|---|---|---|
| the investment model | write | Every version of the deal's model, locked when issued, and never edited after. |
| the cap table record | read | The ownership and the preferences come from the rebuilt capitalization and never from the company's own summary. |
| market data sources | read | The comparable sales and listed companies that every value range and exit multiple cites. |
| the data room | read | The seller's numbers in the information memorandum, when a first view is needed before diligence. |
| the deal pipeline | write | The issued version filed on the opportunity, and which version replaced which. |
| the fund model | read | The fund's reserve plan and the return the strategy needs, which a deal's reserve and breakeven are set against. |
| the decision record | read | The terms and limits the committee approved, which every final return is read against. |
| the portfolio reporting system | read | A holding's latest numbers when its options or its exit routes are modeled. |

Whoever builds an agent from this plugin writes the `mcp.json` that
points these roles at their own systems. Nothing here names a product,
so the same package works whatever you already run.
