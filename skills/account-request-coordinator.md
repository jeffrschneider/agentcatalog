# account-request-coordinator

## take-in-an-account-request

Takes in each request about an account as it arrived, with its channel,
who asks and what they ask for, keeps it unchanged as evidence, and
holds the account so that no sign-in detail, email address or phone
number changes while the request is open.

covers:
- Hold the Account as It Stands
- Keep the Request as Evidence
- Take In the Request

## reach-the-contacts-on-file

Finds the contacts the account held before the request arrived, asks the
signatory or another administrator to confirm a new holder through them,
and tells the existing contacts and the holder what was asked and what
was done, through those details only.

covers:
- Confirm with a Contact on File
- Find the Contacts on File
- Tell the Existing Contacts
- Tell the Holder and the Contacts

## prepare-a-decision-for-a-person

Sets out each handover, each closure and each answer to a data request
with every check behind it, for the named person who decides it: the
access approver, the closure approver or the privacy lead.

covers:
- Prepare the Answer
- Prepare the Closure
- Prepare the Handover

## settle-the-terms-of-a-closure

Sets each request to close against the agreement and the local rules,
lists the invoices still open, offers the customer a copy of its data,
sets out what each system keeps and until when, and confirms the closing
date with the customer.

covers:
- Confirm the Closing Date with the Customer
- List the Invoices Still Open
- Offer the Customer Its Data
- Set What Each System Keeps
- Set the Request Against the Agreement

## tell-the-people-who-must-know

Passes a request to close to the account owner the same day in the
customer's own words, and tells the customer, Finance and the account
owner once the account is closed.

covers:
- Tell Finance and the Account Owner
- Tell the Account Owner the Same Day
- Tell the Customer It Is Closed

## run-a-data-request

Logs each data request with its deadline, acknowledges it in the
approved words, finds the data in every system on the data map, sets
aside other people's details, and searches every system again to confirm
that what was deleted is gone.

covers:
- Acknowledge the Request
- Confirm What Is Gone
- Find the Data in Every System
- Log the Request with Its Deadline
- Set Aside Other People's Details

## close-each-request-on-the-record

Confirms the holder is back in after a handover, records who asked, each
check and how it was made, who decided and what changed, and records
what each recovery and each closure taught.

covers:
- Close the Request on the Record
- Confirm the Holder Is Back In
- Record What the Closure Taught
- Record What the Request Taught
- Record the Closure
- Record the Request
