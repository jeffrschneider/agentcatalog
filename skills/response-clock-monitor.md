# response-clock-monitor

## set-what-each-clock-covers

Takes the promise and the window being measured, and writes down what
starts each clock, what stops it and what pauses it, so that two people
read it the same way. Where a new rule promises a clock, that promise is
written the same way before the rule runs, and once a clock is built
into a system a sample of cases is checked against what the policy says.

covers:
- Name What Each Clock Covers
- Set the Clock the Rule Promises
- Take in the Promise and the Window
- Check the Clocks Against the Policy

## measure-every-run-against-its-clock

Checks first that the stamps hold up, such as missing stops and
back-dated stamps, then marks every run or case in the window met,
missed, or still open past its due time, with its start, its stop, its
queue and its owner. Runs the clock never fitted are set aside with a
written reason and the name of the person who agreed, and the set-aside
count is published beside the result. The same reading runs over the
last periods against the levels in force, and from the day new levels
take effect.

covers:
- Measure Each Run Against Its Clock
- Set Aside What the Clock Does Not Cover
- Check the Stamps Hold Up
- Measure Each Case Against Its Clock
- Read the Results Against Today's Levels
- Measure from the Day It Takes Effect

## watch-the-queues-through-the-day

Watches each queue's waiting cases against their clocks through the day,
names a queue about to miss with the cases at risk and the time each has
left, and checks the queue recovers once a person has changed something.

covers:
- Watch Each Queue Against Its Clock
- Name a Queue About to Miss
- Check the Queue Recovers

## read-what-is-already-promised

Reads the levels each plan and agreement already promises customers, and
checks each candidate level against them, naming every account a
candidate would serve slower than its agreement promises.

covers:
- Read What Customers Are Already Promised
- Check Each Against What Is Promised

## break-the-misses-down

Cuts the misses by queue, owner, source and hour of arrival, with the
count in every cut, and for the support desk by queue, channel, topic,
plan and hour with no named person in any cut. Says what the misses
have in common only as far as the evidence supports saying it.

covers:
- Break the Misses Down
- Find What the Misses Have in Common
- Find the Cause Behind the Misses
- Read Where the Last Schedule Missed

## publish-the-promise-and-the-result

Writes the promise and what actually happened side by side, whether the
number is good or bad, and takes each queue its own number rather than
the average. A new rule or a new schedule gets the same reading over its
first week, and each team lead is taken through their own queues.

covers:
- Take Each Queue Its Own Number
- Watch the First Week
- Write the Report
- Take Each Team Lead Through Their Queues

## keep-a-misrouted-run-on-its-first-clock

Holds the clock where it is when work moves because it reached the wrong
person, so the run stays measured from when it first arrived. The time
that misroute cost is filed against the rule version that produced it.

covers:
- File the Case Against the Rule
- Hold the Clock Where It Is
